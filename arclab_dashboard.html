Pipeline architecture
Source WattTime API — CAISO_NORTH ▼

Real-time and historical carbon intensity data from the WattTime API for the CAISO_NORTH grid region — the California ISO northern zone. WattTime provides marginal operating emissions rate (MOER) data, which reflects the emissions of the generator that would respond to a change in load — a more accurate signal than average grid intensity.

Data is pulled via authenticated API calls and landed in raw form before any transformation is applied.

Bronze Raw ingestion — Delta Lake ▼

Raw API responses are landed as-is into Delta Lake in the Databricks workspace. No transformations are applied at this layer — the Bronze table is an exact copy of the source data, preserving full lineage and enabling replay if something goes wrong downstream.

This is a deliberate design choice. Bronze is your insurance policy. If a transformation bug corrupts Silver or Gold, you can always reprocess from Bronze without re-calling the API.

Silver Cleaned & normalized ▼

The Silver layer handles all normalization work: timestamps are cast and normalized (including the TIMESTAMP_NTZ workaround required in Databricks), nulls are handled, duplicates are removed, and schema is enforced.

A key technical challenge at this layer: TIMESTAMP_NTZ columns don't support standard epoch math in Databricks. The fix is casting through unix_timestamp(col.cast("timestamp")) first.

Gold carbon_intensity_hourly — analytics-ready ▼

The Gold table is where business logic lives: hourly averages are computed, hours are classified as Optimal / Moderate / Avoid based on intensity thresholds, and weekday/weekend splits are applied. This is the table all downstream consumers — the Streamlit app, this dashboard, any BI tool — query against.

Table location: bootcamp_students.gold.carbon_intensity_hourly

App Streamlit + LangChain RAG assistant ▼

The live Streamlit app at arc-lab.streamlit.app sits on top of the Gold table. It provides real-time carbon intensity forecasting, a natural-language RAG assistant powered by LangChain and Databricks Vector Search, token auto-refresh, and a Parquet fallback for when the live connection is unavailable.

The LLM integration uses from databricks_langchain import ChatDatabricks — not the standard LangChain community package, which conflicts at runtime in the Databricks environment.
